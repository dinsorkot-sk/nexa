Nexa · Design References — สำหรับร่าง docs/design.md ใหม่

3 หลัก + 4 เสริม ที่ตรงกับ Nexa จริง

Nexa คือ metadata-driven platform (Module → Entity → Field → Relation → Record) + Builder/Runtime แยกกัน + รองรับ ไทย/อังกฤษ + Light/Dark — ref ที่เลือกจึงต้องแก้ปัญหาเดียวกัน ไม่ใช่แค่สวย

Priority 1 — โครงสร้างข้อมูล

Directus keep

ต้นแบบ Data Studio สำหรับสร้าง collection/field/relation แบบ metadata-driven — แยก โครงสร้าง ออกจาก ข้อมูลจริง ชัดเจนที่สุด

  • Dual-storage: system collections เก็บนิยาม, user collections เก็บข้อมูล
  • Field = column + interface + display + validation + conditional style
  • Relation บอก source/target/type ชัด ไม่ใช้ไอคอนแทนคำอธิบาย
เอาไปใช้: Module/Entity/Field/Relation editor, การจัดกลุ่ม field ตาม task (identity → type/options → validation → display → advanced), lifecycle draft → review → active
Priority 2 — การใช้งานประจำวัน

Linear keep

List-first, keyboard-first, optimistic UI — มาตรฐานที่ทีม dev คาดหวังในปี 2025-26

  • Cmd+K command palette, single-letter shortcuts (c, a, p, s), hover โชว์ shortcut
  • ตาราง dense แต่ไม่อึดอัด — row height 32/40px rhythm เดียวกันทั้งแอป
  • Motion 120–180ms บอก state change ไม่ได้ทำให้รอ
เอาไปใช้: Record lists, toolbar search/filter/sort, bulk action, MetaTable row interaction, focus/hover/selected/disabled states
Priority 3 — องค์ประกอบ & เลย์เอาต์

Nuxt UI keep

Dashboard composition มาตรฐานของ Nuxt — Sidebar/Panel/Navbar/Toolbar ที่ตรงกับสแต็ก Nexa (Nuxt 4)

  • DashboardGroup → Sidebar (resizable/collapsible/persist) + Panel (header/body/footer)
  • Container / spacing 4px rhythm / responsive collapse เป็น drawer
  • Theme-aware component ขาว/ดำ ผ่าน semantic tokens
เอาไปใช้: App shell, sidebar collapse, page header + primary action, toolbar/filter row, responsive strategy

Ref เสริม — เติมจุดที่ 3 หลักยังไม่ครอบคลุม

Supabase emerald

โทน emerald/dark เดียวกับ Nexa, table editor + SQL + auth ใน dashboard เดียว — ดูการจัดวาง data-dense control โดยไม่รก

Notion

Warm minimal + block/property system — ไอเดีย property types, database view สลับ Table/Board/Calendar ที่ Nexa จะมีต่อ

Stripe

น้ำหนัก type 300 + shadow สี brand, ตัวอย่างการใช้ semantic token อย่างมีวินัย — เทียบกับ Slate+Emerald ของ Nexa

Vercel / Geist

Shadow-as-border, multi-layer elevation, Geist tracking — เทคนิคเชิงลึกสำหรับยกระดับ card/overlay โดยไม่เพิ่มสีใหม่

ข้อเสนอสำหรับ design.md ใหม่: คง 3 หลักไว้ (Directus/Linear/Nuxt UI) แล้วเพิ่ม “Secondary refs” เป็น Supabase + Notion แบบระบุเงื่อนไขว่าใช้เมื่อใด — ไม่ยก Stripe/Vercel เป็น ref หลักเพราะบุคลิกห่างจาก enterprise builder ของ Nexa มาก แต่ยืมเทคนิค token/shadow มาได้
